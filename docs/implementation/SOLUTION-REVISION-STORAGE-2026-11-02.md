# Solution Revision 저장 기반

## 현재 구현 범위

`src/solution-revision-store.ts`는 v15의 SolutionRevision을 보관하는 Builder 내부 모듈이다.
Core에 Graph나 Lead 역할을 추가하지 않고 공개 SDK의 회사 범위 KV와 선택적 조건부 저장을
사용한다. Workspace 안에서도 Builder 프로젝트 ID별로 별도 기록과 현재 버전을 유지한다.
Core 프로젝트를 생성하거나 프로젝트 폴더를 지정하는 기능이 아니다.

이 모듈은 아직 AI 도구, 사용자 편집 Action, UI 또는 실행 경로에 등록하지 않았다.
Lead 호출자·현재 세션/Run, 선택 버전, 해당 프로젝트 명세와 근거 검증을 연결하기 전에는
설계 변경 API로 노출하지 않는다. `approvedSpecRevisionId`가 저장됐다는 사실은 실제 명세
승인이나 해당 명세의 존재를 검증했다는 뜻이 아니다.

## 저장 순서와 한계

1. 순수 Graph 검증기를 재사용해 새 Revision의 데이터와 의존성 DAG를 검증한다.
2. 새 Revision을 별도 키에 조건부 생성한다. 이 모듈의 쓰기 경로는 같은 ID의 기존 내용을 덮어쓰지 않는다.
3. 읽었던 현재 버전과 일치할 때만 현재 버전 포인터를 조건부로 바꾼다.
4. 조회는 현재 포인터에서 연결되는 기록만 보여 준다. 미확정 개정안은 확정 이력에 섞지 않는다.

두 키를 하나의 DB transaction으로 묶었다는 뜻은 아니다. 2단계 이후 실패하면 미확정
레코드가 남을 수 있다. 자동 삭제·전체 저장소 수선·자동 재전송은 하지 않는다. 응답 유실은
저장 결과 불명 상태일 수 있으므로 오류를 드러내고 다음 명시적 조회로 확인해야 한다.

기록의 해시는 저장 무결성 대조용이다. 작성자 인증, 서명, 외부 검증 증거 또는 악의적인
플러그인의 전체 KV 접근을 제한하는 보안 장치가 아니다. Lead 전용 업무 권한과 Core의
호출·Workspace 권한 검사는 별도로 연결해야 한다.

## 크기와 조회

각 레코드는 192 KiB 이하이며, 현재 기록과 최근 최대 50개 개정안을 읽는다.
`hasMore`는 오래된 이력이 남아 있음을 알린다. 전체 이력 페이지 탐색, 장기 보관·정리,
UI 분할 응답은 아직 구현하지 않았다. 한계를 넘는 설계를 조용히 자르거나 성공으로 표시하지 않는다.

## 완료로 보지 않는 항목

이 기반만으로 AC-02·AC-05·AC-89·AC-105 또는 Builder 전체를 통과 처리하지 않는다.
실제 Lead 도구 호출, 명세·계약 참조 검증, 권한 변경 경합, 공유 기억과 UI 동기화가 남는다.
Marketplace·Preview·자체 LAN은 계속 보류다. 사용자 DEV 의존성이나 설치본에 적용한 변경도 아니다.

# 현재 인수 기준 추적표

[기계 판독 추적표](AC-TRACE-2026-11-04.json)는 실제 원문 정의를 읽어 작성했다.
기본 v15 118개, CSAS v0.8 44개, 상담 개정 8개로 **서로 다른 정의 ID는 170개**다.
원문·소스 해시·행·개정과 후속 정책 적용 관계를 함께 보존한다.
이는 170개의 서로 독립적인 요구사항이나 170개 시험 통과를 뜻하지 않는다.
과거의 162개는 첫 두 문서만 합친 정의 수이며 상담 개정 8개는 별도다.

## 현행 범위

- 레거시 전환 AC-CSAS-LEGACY-01~06은 최신 사용자 결정으로 구현 범위에서 제외한다.
  원문을 삭제하거나 PASS로 계산하지 않는다.
- AC-10/25/66의 보류한 Preview 부분과 나머지 유효 요구를 구분한다.
  제품 HTML 승인 뷰어를 Core Preview 보류와 함께 제외하지 않는다.
- 옛 3세션·Batch-only 문구는 [현재 통합 계약](CURRENT-PRODUCT-CONTRACT-2026-11-04.md)의
  5세션·실시간 수집/명시 분석 결정으로 해석한다. 나머지 요구는 유지한다.
- 기존 AC와 CSAS/상담 확장의 구체 `extends` 및 CTO Task 연결은 추가로 대조해야 한다.
  원문 ID가 다르다는 이유만으로 서로 독립된 요구라고 자동 판단하지 않는다.

## 상태와 증거

초기 `NOT_RUN`은 **해당 현행 AC 전체를 현재 소스에 연결해 인수 판정하지 않았음**을
뜻한다. 기존 모듈/실제 AI/앱 시험이 한 번도 없었다는 뜻이 아니다.
해당 AC 전체 범위를 충족하는 증거를 연결하기 전에는 과거 시험이나 일부 검사만으로
PASS로 바꾸지 않는다. 현재 표의 전체 AC 합격 선언은 0개다.

담당 CTO·정확한 대상 Revision·실제 시험 이름·관측 결과·범위·제한을 확인해
각 행을 갱신한다. 부분 증거는 부분이라고 설명하고, UNKNOWN/BLOCKED/FAIL을
누락하거나 문서 수·커밋 수·계획 접수로 대체하지 않는다.

`attachment:` 원문은 사용자가 제공한 CSAS v0.8이다. 첨부 자체가 저장소에
포함됐다는 뜻이 아니다. 일반 인수 기준의 해당 원문 문장과 파일 해시를 표에 남겼으며
비공개 Core 코드·인증정보·사용자 실행 기록을 복사하지 않았다.

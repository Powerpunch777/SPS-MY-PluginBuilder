# Builder UI 적용 기준

2026-11-01 사용자 결정. 통합 설계 v15와 HTML UI v9를 대체하지 않고, 실제
제품에 적용할 시각 기준과 예외를 명시한다.

## 우선 기준

1. 업무·권한·세션·데이터 경계는 통합 설계 v15를 따른다.
2. 화면 구조·정보 배치·패널·탐색 흐름은 `SPS_Builder_Lead_UI_v9.html`을 따른다.
3. 색상은 사용자의 최신 요청에 따라 Codex처럼 검정·짙은 중립 회색을 사용한다.
   원본 시안의 네이비 팔레트나 앞선 임시 구현의 밝은 녹색 테마는 적용하지 않는다.
4. Core의 전역 테마와 Builder의 UI 기준은 별개다. Builder 스타일은 플러그인
   영역에만 적용하고 Core 및 다른 플러그인의 화면을 바꾸지 않는다.

## 유지할 구조

- 왼쪽 Workspace·주 메뉴·현재 활성 AI 목록과 아래 프로필/설정 진입 위치.
- 중복된 공통 상단 바 없이 Lead 대화 안의 단일 헤더·대화·입력창 구성.
- 오른쪽 AI 작업 패널의 수정사항·작업 지시·기록·작업 파일·설계 위치.
- 선택한 하위 AI의 읽기 전용 세션과 해당 AI 범위의 기록 구분.
- 설계 시각화·조직도·설계 문서·미결정사항·시스템의 시안별 배치.
- 작은 화면의 사이드바 축소와 패널 열기/닫기. 겹침이나 수평 잘림은 허용하지 않는다.

## 시각·상태 규칙

배경과 표면은 검정·짙은 회색, 글자는 밝은 중립색, 테두리는 절제된 회색을
사용한다. 큰 초록색 면이나 네이비·보라색 그라데이션으로 바꾸지 않는다.
상태 색상은 실제 상태를 구분할 작은 표식에 한정한다. 시안의 한글 폰트 구성,
읽기 쉬운 크기·줄간격·둥근 모서리·여백을 유지하되 자간은 0으로 둔다.

UI 시안의 샘플 대화·가짜 CTO·변경안·Runner·완료율을 실제 데이터처럼 복사하지
않는다. 현재 데이터가 있으면 해당 범위만 연결하고, 데이터 계약이나 기능이
없으면 원래 위치를 유지한 채 미연결/사용 불가 상태로 표시한다. 시안과 비슷하게
보이게 하려고 실행·기억·승인·검증이 완료됐다고 표시하지 않는다.

실제 API 연결을 위해 React 컴포넌트와 접근성 처리를 작성하는 것은 가능하지만,
이를 이유로 레이아웃·색상·폰트를 임의로 다시 디자인하지 않는다. 새로운 화면
구조나 사용자 결정을 요구하는 변경은 먼저 사용자에게 확인한다.

## 검증 및 현재 상태

앞선 밝은 임시 구현은 이 기준에 맞지 않는다. 현재 검정 팔레트·단일 Lead 헤더·
5개 작업 탭·프로필 설정 진입을 반영했으며, 연결되지 않은 수정사항/작업 지시/
작업 파일은 비활성으로 표시한다. 기록·설계 조회에는 실제 snapshot만 사용한다.
브라우저의 데스크톱/모바일·임베디드 폭 검사는 통과했다. 이어 격리된 source-only
Electron/Core Host에서도 검정 테마·단일 Lead 헤더·5개 작업 탭과 기존 Workspace
분리·명시적 저장·재시작 후 보존을 확인했다. 이 검사는 Builder `2f29523`, Source
`0cf4cb8`, Core `f8ef641`에서 수행했으며, 실제 Host에 복사한 UI 파일의 SHA-256은
`5357a044517da9665cd35a7e152c855cad6990f89958e66ed1d20f1575c0ed75`이다.
시험 Main 4개와 출력 스트림 8개의 종료 및 격리 임시 데이터 정리도 확인했다.

후속 보정에서는 설계 Graph의 선택 노드 상세 패널을 실제 snapshot의 유형·상태·
담당 Actor·연결 관계에 연결했다. 노드 선택은 상세 조회만 하고, 담당 Actor 기록은
별도 읽기 전용 버튼으로 연다. 담당자가 없으면 해당 버튼은 비활성이다. v9 시안처럼
이 화면에는 대화용 작업 기록 패널을 중복 배치하지 않고 Graph와 상세 영역만 둔다.
키보드 선택·확대율 맞춤·모바일 세로 배치와 담당 Actor 조회 전환을 브라우저에서
확인했다. 설명·현재 작업·변경 승인·Graph 편집을 샘플 데이터로 채우지 않았다.
정확한 후보·해시·실제 Host 검사 범위와 남은 공백은
[Graph 상세 검증 기록](../../implementation/GRAPH-DETAIL-VALIDATION-2026-11-01.md)에 구분했다.

설계 문서는 v9의 프로젝트 파일/미리보기 두 칸을 빈 상태에도 유지하며, 실제
Workspace 문서의 본문·Revision·시각만 조회한다. 이 화면에도 대화용 작업 기록
패널을 중복 배치하지 않는다. 현재 snapshot에는 프로젝트 구분 필드가 없어 그
제한을 안내하고, 프로젝트별 분류·외부 파일 탐색·편집·다운로드가 연결됐다고
표시하지 않는다. 새 snapshot에서 선택 문서가 사라지거나 목록이 비는 경우도
브라우저에서 확인했다. 시험용 문서는 개발 Preview fixture에만 존재한다.

문서 UI runtime `43aa63a558bc6b438fbd8bdeda1ec07d0d9be65e`는 Node24의
`npm run check`36/36·SDK 검사와 desktop/mobile/embedded 브라우저 검사를 통과했다.
해당 커밋 CI `41314559820`도 Node22.18/24와 Browser 작업이 모두 통과했다.
Source `e04ab794` / Core `f8ef641e` / SDK `61a929f6`의 source-only 실제 Host에서는
실제 데이터가 비어 있는 문서 2칸·중복 rail 없음·가로 넘침 없음과 기존
저장/분리/재시작 흐름을 확인했다. Main 4개 정상 종료·출력 스트림 8개 종료·정확한
임시 데이터 정리를 확인하고 exit0으로 끝났다. 내용이 있는 문서의 선택·갱신은
개발 fixture 증거이며 실제 AI 문서 생성이나 프로젝트별 저장 계약 검증은 아니다.
실제 Host에 복사한 `index.js` SHA-256은
`55c3c54991707720e5d5d250b217b9b63f9127ae0d3a3177ba692525ccdafb4d`이고,
SDK의 UI 디렉터리 fingerprint는
`05bf2486129f559fe11d0d17624ba25ae5fe1b06254c0a34462129a04960f645`이다.
두 해시는 서로 다른 대상을 측정한다. 설치본·실기기·전체 자손 종료 증거는 아니다.

조직도 후속 보정은 저장된 `parentActorId`를 유지하면서 Lead와 같은 부모의 하위
Actor를 v9처럼 행으로 배치한다. 각 CTO의 Worker는 실제 부모 아래에 남고, 좁은
화면에서는 줄바꿈한다. 대화용 rail은 표시하지 않는다. 버튼은 Lead 대화 또는
하위 Actor의 읽기 전용 기록을 열 뿐 세션 생성·실행·새 Actor를 추가하지 않는다.
Lead가 활성 Worker 목록에 섞이지 않는지와 부모별 배치·넘침·조회 전환을
브라우저에서 확인한다. 채워진 조직은 개발 fixture이며 실제 AI 실행 증거가 아니다.
정상 fixture는 기존 snapshot 검증의 끊어진 부모·순환 관계 거부 원칙을 따른다.

조직도 runtime `0a935e38ece5aa7e5f1a7c28d4af6439ab0e8134`의 Node24 검사36/36·
SDK 검사·desktop/mobile/embedded 브라우저 검사와 CI `41315905793`은 통과했다.
Source `238c8aa2` / Core `f8ef641e` / SDK `61a929f6`의 source-only 실제 Host에서도
빈 조직에 Actor를 지어내지 않는 화면과 중복 rail 없음, 기존 저장·격리·재시작을
확인했다. Main 4개 정상 종료·출력 8개 종료·정확한 임시 데이터 정리 후 exit0이다.
실제 Host가 로드한 UI index SHA-256은
`c099f8b77d49656c5117bd5395fd0f44c2752f2759bee30a47a77d9a6bba4ba0`,
SDK UI 디렉터리 fingerprint는
`ff85f1babe1ba543bf19a5adcdfbc46d8b2ff86be92e22308dfe55c777d119a6`이다.
채워진 조직·Worker 기록 전환은 개발 fixture 검증이며 실제 AI 실행·프로젝트별
CTO 단일 세션·독립 Dev/QA 실행·두 PC·서명 설치본의 검증은 여전히 별개다.

다만 설계 시각화의 나머지 모드·문서/조직도/시스템의 전체 v9 구성은 아직 남아 있다.
시스템 화면의 후속 배치는 대화용 작업 패널과 토글을 제거하고 연결 상태/Runner
영역을 본문 폭에 맞췄다. Workspace 연결 상태와 미연결 Runner 안내를 구분하며
기존 Lead Agent 선택·저장을 유지한다. 개발 용어 대신 쉬운 한국어로 안내한다.
Node24 검사36/36·SDK 검사·desktop/mobile/embedded 브라우저 및 실제 source Host의
구체적인 DOM·저장·재시작 검증은
[시스템 화면 검증 기록](../../implementation/SYSTEM-UI-VALIDATION-2026-11-02.md)을 따른다.
Runner 인벤토리·접속 상태·실행이나 System 전체 v9 기능이 완성된 것은 아니다.
위 결과는 서명 설치본·실제 AI 실행·두 PC 검증이 아니며, 이 문서나 초기 캡처를
UI 전체 반영 완료 증거로 사용하지 않는다.

원본 시안과 실제 화면을 같은 크기로 캡처해 배치·비율을
비교하고, 검정 팔레트·폰트·패널·입력창·실제 데이터 범위와 데스크톱/모바일
조작을 확인한다. 브라우저 검증과 실제 Core Host 통합 검증을 별도로 기록한다.
UI가 닮았다는 사실은 실제 Lead/CTO/Worker 실행이나 공유 기억 완료를 뜻하지 않는다.

Core 내장 탐색이 차지하는 폭 때문에, 플러그인 컨테이너가 좁으면 원본 시안보다
일찍 오른쪽 패널을 drawer로 전환한다. 기본 데스크톱의 240px 사이드바와 384px
작업 패널은 유지한다. 이 반응형 보정은 화면 구성이나 업무 기능의 축소가 아니다.
